# PPO Highway Driving：高速公路驾驶决策与风险场景评估

基于 [HighwayEnv](https://github.com/Farama-Foundation/HighwayEnv) 和 [Stable-Baselines3](https://github.com/DLR-RM/stable-baselines3) PPO 的强化学习驾驶项目。

本项目从“模型通过低速保守行驶减少碰撞”的问题出发，逐步实现持续交通刷新、安全奖励、固定慢车混合训练、车道速度规则、限时路程任务以及随机背景车行为，并使用随机动作和保持直行策略进行对照评估。

最新模型在 **30轮随机交通评估中，成功率为96.7%，碰撞率为3.3%，平均速度为34.83 m/s**。结果来自自定义仿真场景；当前仍有车道速度违规、无效动作和突发风险覆盖不足等问题。

## 1. 项目目标与工作范围

在持续存在背景交通的四车道高速公路上，自车需要在60秒内向前行驶1800米，同时减少碰撞、危险跟车、不安全变道及车道速度违规。

项目主要工作包括：

- 自定义环境与交通生成、清理和补充机制。
- 安全、速度匹配、任务完成及持续低速占道奖励。
- 车辆状态与任务进度观测设计。
- 固定慢车场景和随机交通行为设计。
- 基线对比、失败案例分析及模型版本管理。

PPO使用Stable-Baselines3提供的实现，本项目未修改PPO的核心优化算法。背景车辆使用IDM跟车与自定义变道规则，自车由PPO控制。本项目研究高层驾驶决策，不包含摄像头感知、真实车辆部署或完整自动驾驶系统。

## 2. 环境设计

### 2.1 道路与速度规则

| 车道编号 | 位置 | 正常期望速度区间 | 约合 km/h |
| --- | --- | --- | --- |
| 0 | 最左侧 | 35～40 m/s | 126～144 |
| 1 | 左侧第二条 | 30～35 m/s | 108～126 |
| 2 | 右侧第二条 | 25～30 m/s | 90～108 |
| 3 | 最右侧 | 20～25 m/s | 72～90 |

这是实验设定，不对应特定地区的实际交通法规。自车初始位于车道1，速度30 m/s。

车道规则不是自车的硬约束：自车通过奖励学习遵守。背景车的正常期望速度按所在车道采样，实际速度由跟车和加减速决定；危险时允许低于最低速度。进入新车道后，车辆需要逐渐适应新的期望速度。

### 2.2 持续交通窗口

- 初始每条车道生成6辆背景车，共24辆，分布在自车前后。
- 保留自车前后各400米的交通窗口，清理远离窗口的背景车。
- 各车道前后边界使用独立到达时钟，默认平均到达间隔3秒。
- 在距自车365～395米的边界区域尝试补车，每条车道最多8辆背景车。
- 新车生成前检查车身间距、跟车时间和相对速度，没有安全空间则跳过。
- 使用环境随机数生成器，支持按种子复现实验。

补车不是无条件生成。安全间距、车辆上限和交通演化都会影响窗口内的实际车辆数量。

### 2.3 随机背景车行为

- 背景车每隔3～5秒随机调整一次期望速度，实际速度不会瞬间跳变。
- 每次事件以60%的概率尝试随机进入相邻车道。
- 变道前检查目标车道前后空间及附近汇入车辆；没有空间就保持车道。
- 进入新车道后重新采样对应的期望速度。
- 每辆背景车生成时有5%的概率被设为速度违规车辆，允许低速违规或超速；仍保留跟车和变道安全检查。

60%是变道尝试概率，不是成功变道概率；5%是车辆类型概率，不是每一步违规概率。随机事件也不保证形成明显的危险场景。

## 3. 强化学习建模

### 3.1 观测：88维

| 观测内容 | 维度 | 含义 |
| --- | --- | --- |
| Kinematics车辆状态 | 17×5=85 | presence、x、y、vx、vy |
| 剩余时间比例 | 1 | 剩余时间 / 时间上限 |
| 剩余路程比例 | 1 | 剩余路程 / 目标路程 |
| 持续低速计时比例 | 1 | 当前低速计时 / 两倍宽限时间 |

车辆状态归一化并展平，背景车使用相对位置和速度，允许观察后方车辆。17个车辆槽位通常包含自车和最多16辆背景车，并不保证各车道最近前后车都进入观测。

### 3.2 动作：5个离散高层动作

| 编号 | 动作 | 含义 |
| --- | --- | --- |
| 0 | LANE_LEFT | 请求向左变道 |
| 1 | IDLE | 保持目标速度和目标车道 |
| 2 | LANE_RIGHT | 请求向右变道 |
| 3 | FASTER | 提高目标速度档位 |
| 4 | SLOWER | 降低目标速度档位 |

目标速度档位为10、15、20、25、30、35、40、45 m/s。实际速度通过底层控制逐渐变化。IDLE不是停车；在最左侧继续请求向左变道不会产生实际变道。

### 3.3 PPO设置

PPO使用新旧策略概率比和裁剪目标限制单次策略更新幅度，同时训练价值网络。`MlpPolicy`表示采用MLP网络的策略实现，不是本项目自定义的强化学习算法。

| 参数 | 设置 |
| --- | --- |
| learning_rate | 3e-4 |
| n_steps | 1024 |
| batch_size | 64 |
| n_epochs | 10 |
| gamma | 0.99 |
| gae_lambda | 0.95 |
| clip_range | 0.2 |
| ent_coef | 0.01 |
| 训练设备 | CPU |
| 最新模型实际训练步数 | 500,736 |

指定训练500,000步时，PPO按完整rollout收集数据，实际步数可能略高。

### 3.4 奖励与风险

奖励由速度匹配项减去各项风险和违规处罚，再加入安全完成奖励或超时处罚。

| 分项 | 当前权重或设置 | 作用 |
| --- | --- | --- |
| speed_tracking | 1 | 偏离当前车道偏好速度时给予负值 |
| speed_violation | 1 | 处罚低于车道下限或高于上限 |
| front_risk | 2 | 处罚当前及目标车道的前车风险 |
| unsafe_lane_change | 2 | 处罚变道过程中目标车道后车风险 |
| slow_lane_stay | 1 | 处罚具备安全右移条件时的持续低速占道 |
| collision | 100 | 碰撞处罚 |
| offroad | 100 | 驶离道路处罚 |
| success_bonus | 10 | 安全完成1800米任务 |
| timeout_penalty | 5 | 超时未完成任务 |
| deadline_speed_weight | 0 | 当前关闭额外赶进度处罚 |
| step_time_cost | 0 | 当前关闭每步时间成本 |

偏好速度取当前车道速度中点与“剩余路程 / 剩余时间”的较大值，并限制在该车道速度区间内。因此额外赶进度处罚关闭后，任务进度仍会影响速度匹配项。

前车风险综合车间距不足和预计碰撞时间TTC，取两者最大值，范围为0～1。危险时减轻低速和速度偏差处罚，允许减速避险。

持续低速占道处罚需同时满足：

1. 低于当前车道最低速度超过0.5 m/s，并稳定保持本车道。
2. 前车风险不超过0.05，连续低速超过5秒。
3. 右侧存在车道，且其速度范围与当前实际速度匹配。
4. 右侧车道前后空间满足安全检查。

处罚从第5秒后逐渐增加，到第10秒达到最大值1。前方危险、恢复正常速度或开始变道时清零计时。该奖励允许模型恢复速度或选择合适车道，不会强制右移。

## 4. 修改历程与实验结果

### 4.1 版本记录

| 版本 | 模型文件 | 主要改动 | 已记录表现 |
| --- | --- | --- | --- |
| V1 | ppo_continuous.zip | 持续交通窗口、安全与速度奖励 | 碰撞率10%，均速24.99 m/s |
| V2 | ppo_continuous_mixed.zip | 正常交通与固定慢车混合训练 | 固定慢车碰撞率20%，均速25.76 m/s |
| V3 | ppo_lane_20261010_171756_078398.zip | 车道速度、限时路程和任务进度观测 | 碰撞率100%，成功率0%，约4秒结束 |
| V4 | ppo_lane_20261010_221731_373451.zip | 提高失败成本，关闭额外时间及赶进度处罚 | 固定慢车成功率100%；随机交通成功率93.3% |
| V5 | ppo_lane_20261011_172837_779889.zip | 随机交通、持续低速占道处罚、88维观测 | 随机交通成功率96.7%，碰撞率3.3% |

V1、V2的名称对应依据开发记录；V3～V5的对应关系由评估JSON中的模型字段确认。

V3提供了一个失败案例：当每步主要获得负奖励、碰撞会结束回合时，可能出现提前结束减少后续处罚的动机。提高失败成本后表现改善，但由于同时修改了其他设置，尚未通过消融实验证明这一因素是唯一原因。

### 4.2 最新模型与基线对比

模型：`ppo_lane_20261011_172837_779889.zip`。

报告：`results/evaluation_random_traffic_20261012_025256_016165.json`。

30轮随机交通评估，重置种子为1000～1029，PPO采用确定性动作预测。

| 策略 | 平均回报 | 平均速度 m/s | 速度违规时间比例 | 前车风险时间比例 | 碰撞率 | 平均回合时间 s | 平均距离 m | 成功率 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| random | -127.706 | 27.481 | 74.3% | 25.5% | 96.7% | 23.317 | 588.949 | 0% |
| idle | -25.587 | 29.998 | 0% | 3.8% | 6.7% | 58.850 | 1647.746 | 0% |
| ppo | -9.318 | 34.825 | 43.2% | 11.8% | 3.3% | 54.883 | 1780.910 | 96.7% |

- random：每步随机选择动作。
- idle：持续执行IDLE，保持目标速度和车道，不具备自动避险决策。
- ppo：依据当前观测选择动作。

PPO约29轮成功、1轮碰撞；平均距离包含失败回合，因此低于1800米不代表成功回合未完成目标。

### 4.4 指标解释

- `return`：一轮累计奖励。
- `mean_speed`：一轮决策步上的实际速度平均值。
- `speed_violation_fraction`：实际速度不满足当前所属车道区间的步数比例。
- `front_risk_fraction`：前车风险大于0的步数比例，不等于碰撞概率。
- `crashed`：一轮是否碰撞，汇总平均值为碰撞率。
- `duration_seconds`：环境记录的回合时间。
- `distance`：相对初始位置的向前位移。
- `success`：安全达到路程目标；应与回合时间一起判断按时完成情况。

代码先计算每轮指标，再跨回合取平均，时间比例不是把所有回合的步数合并后计算。同一重置种子提供相同初始化与随机生成规则，但不同策略会影响背景车反应和刷新，不能保证完全相同的交通轨迹。

### 5.2 创建环境

```bash
conda create -n highway python=3.10 -y
conda activate highway
python -m pip install --upgrade pip
```

使用HighwayEnv源码安装：

```bash
git clone https://github.com/Farama-Foundation/HighwayEnv.git
cd HighwayEnv
python -m pip install -e .
```

然后安装训练依赖，并进入本项目根目录：

```bash
python -m pip install stable-baselines3
```

以上会取得安装时可用的版本，并不自动恢复开发时的依赖。取得原始HighwayEnv提交和经过验证的环境文件后，应优先按它们安装。

Windows下，如果`noise`安装报Microsoft Visual C++缺失，可先尝试：

```bash
conda install -c conda-forge noise
```

再重新执行依赖安装。若当前平台没有相应预编译包，可安装Microsoft C++ Build Tools的C++桌面开发组件。

如果终端环境名称与实际解释器不一致，可在PowerShell显式指定解释器；将路径换成自己的安装路径：

```powershell
$highwayPython = "D:\anaconda3\envs\highway\python.exe"
& $highwayPython --version
& $highwayPython run.py smoke
```

### 5.3 环境检查

```bash
python run.py smoke
```

smoke展示背景交通，自车持续执行IDLE，不加载PPO。碰撞或完成目标仍会提前结束，设置更长duration并不保证播放满该时间。

### 5.4 展示最新模型

确保模型和同名前缀的配置都位于`models/`：

```bash
python run.py demo --seed 1002 --model ppo_lane_20261011_172837_779889.zip
```

### 5.5 评估

```bash
python run.py evaluate --episodes 30 --model ppo_lane_20261011_172837_779889.zip
```

评估依次运行random、idle和ppo，并将独立命名的报告保存到`results/`。

### 5.6 重新训练

```bash
python run.py train --steps 500000 --seed 42
```

当前训练为随机交通，`slow_front_probability=0.0`；每次从头创建PPO模型，不自动接续旧权重。模型、配置和训练日志采用独立名称。

省略`--model`时，程序选择具有配套配置、修改时间最新的新格式模型。复现实验建议明确指定模型。

### 5.7 历史模型兼容性

- 最新环境观测为88维，早期模型可能为85或87维，不能直接混用。
- 保存的配置不能还原旧版本Python类的实现，历史版本需要对应环境源码。
- 旧式`ppo_continuous.zip`与`config.json`不符合当前自动配对命名，需要旧版加载逻辑。
- 展示和评估读取模型的配套配置，因此旧配置可能覆盖最新默认参数。
- 固定慢车函数仍保留，但最新evaluate/demo默认不调用。新随机车辆类会继续更新目标速度，因此不能只取消注释就声称严格复现旧固定慢车场景。

## 7. 当前限制与后续工作

1. **车道速度违规仍较多。** 需要区分避险减速、无风险持续低速、变道过渡及数值误差，补充违规幅度和持续时间统计。
2. **存在边界无效动作。** 在车道0重复LANE_LEFT不能说明发生了避让，应记录实际变道和无效请求。
3. **相邻车道信息可能不足。** 有限观测槽位不保证各车道最近前后车辆都入选，可增加按车道组织的净间距、相对速度和TTC。
4. **随机交通不等于风险专项测试。** 应补充前车合法减速、邻车切入、后车接近等可控场景，并记录事件后的最小间距和TTC。
5. **变道安全处罚可能提前结束。** 当前风险分项使用当前与目标车道是否不同判断变道，车道归属更新可能早于车身居中。
6. **达到目标即结束。** 末尾正在上升的风险不一定得到后续验证，应增加持续驾驶安全测试。
7. **按时完成判定需要更严格。** 当前success主要判断安全达到目标；可增加显式截止时间检查，并核对目标与超时同一步发生的情况。
8. **评估规模有限。** 当前结果主要来自30轮及有限训练种子，应扩大测试种子、加入多训练种子和置信区间。
9. **缺少严格消融实验。** 后续应固定交通和评估配置，分别比较持续交通、慢车训练、任务观测及占道处罚的贡献。
10. **历史复现资料不完整。** 应记录源码提交、依赖环境、观测版本、场景配置和训练种子，建立每个模型对应的实验清单。

## 8. 项目介绍

> 我基于HighwayEnv和PPO实现了高速公路驾驶决策项目，重点研究奖励设计与风险场景覆盖。针对低速保守策略，加入持续交通、慢车混合训练和限时路程任务，并分析奖励失衡导致早期碰撞的问题。最新模型在30轮随机交通测试中完成率为96.7%、碰撞率为3.3%，同时保留了速度违规和无效动作等失败现象，后续通过独立风险场景与消融实验继续改进。
